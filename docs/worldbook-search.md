# 游玩中的世界书补查

正文 Agent 在自由故事和剧本模式下，以及共享后台 Agent 的候选生成、结算、人物设计、世界书筛选任务中，均可调用 `worldbook_search`。后台调用按所属前台对话查找世界书。现有自动注入继续工作；工具提供候选池以外的补查入口。SillyTavern 严格兼容请求仍沿用原有工具限制。

一次调用只选择一种方式：

```json
{"query":"少林 门规", "limit":5, "offset":0}
```

搜索当前绑定世界书的可用条目，返回编号、标题、静态命中片段、匹配词和是否含模板。返回 `total`、`hasMore`，可分页或改写查询。空格分隔的查询短语保持完整，标题匹配优先于正文泛匹配。它是词面检索，不保证语义相关；模型应先判断片段再阅读。

```json
{"refs":["entry:62", "entry:63"]}
```

按编号读取最多 5 条完整渲染正文。复用世界书预处理、常驻控制器和只读模板投影，返回 `ok`、`empty` 或 `render-error`。失败不会用原始模板代码替代正文。编号限定在当前绑定世界书，不接受任意文件路径；世界书修改后应重新搜索确认。

禁用条目、空正文和 MVU 更新规则不进入可查询集合。自动召回关键词条件、冷却和 BM25 候选裁剪不限制显式补查。工具不更新冷却记录，不保存模板变量变更，也不把读取条目写入常驻提示词。

搜索不执行全书模板；仅动态生成、在静态正文中不存在的内容可能无法搜到，可尝试按条目标题或作者配置的主关键词查询。工具定义包含使用指引；能调用工具不等于模型每轮都会主动补查。

前台本轮成功完整读取的条目，会随结算、候选生成和人物设计任务单向交接给后台。内容来自当前已提交正文轮次的原生工具回执，按编号保留最后一次成功读取；搜索片段、失败结果及其他轮次不传。回退与重生成按当前正文轮次定位，缺少原生记录时不猜测补齐。交接附在后台本次任务消息中，不改变固定系统前缀，也不把后台检索结果回灌前台。动态正文标注为前台读取时的快照，后台需要最新状态时应重新查阅。


## 本局虚拟 Skill 策略

世界书设置仍默认使用原有关键词注入。选择「本局原生 Skill 库」后，原始世界书 JSON 仍是唯一事实来源；派生索引不改写正文、不运行模板、不调用模型或 embedding 服务。

- 静态常驻条目每次请求在固定前部读取最新原文，不写入聊天历史。
- 静态非常驻条目通过字符 2/3-gram、TF-IDF、余弦稀疏图和 Leiden 分组。每类生成实体 `SKILL.md`：整组原文合计本地估算不超过 2000 token 时，按条目分节直接内联；超过阈值时整组外置到 `references/中文标题--ID.md`，由原生 `read` 按需读取，不做部分内联。阈值只估算原文（ASCII 约 4 字符/token，其他字符约 0.6 token/字符），不是模型账单计量。文件布局随原文变化自动切换并清理旧副本，不生成独立 `INDEX.md`。即使有显式激活请求，静态非常驻正文仍只通过 Skill 资源读取。
- 对外名称与描述不用聚类词片：清理标题中的机械编号与已知控制标签，以完整标题的共同分段命名；只有全部成员明确声明同一类别时才采用该类别。描述列出成员名称和原文共有字段，没有结构时直接列资料名。调用名由中文主题在本地转为无声调拼音（如 `ke-ju`），无 `wb-` 前缀；重名加短数字后缀。全过程不调用 LLM，不翻译或改写条目正文。
- 动态常驻条目首次渲染后，依赖或明确执行时机变化时重新评估；动态非常驻条目先经过原生激活条件。按条目身份与渲染哈希仅注入变化，并保存最新有效快照，压缩或冷启动后从实际上下文判断是否需要恢复。
- 无法证明纯读取的 EJS、装饰器和宏保留原生执行时机，不能把静态分析当作副作用安全证明。同一执行轮缓存结果，不为检测变化重复执行或重新抽样。

派生文件位于酒馆数据目录的 `worldbook-skills/<人物卡文件名>/<中文主题>/`，无人物卡时使用世界书名称；同名对局以 `--2` 等数字后缀隔离，重启保留已分配路径。内部归属信息保存在隐藏元数据中，旧哈希目录在生成成功后清理。主题目录不附加内部 ID，仅重名时添加短数字后缀；不放进全局 Skill 扫描目录。因各局共用工作目录，仍由按局 Provider 注册到原生 Skill 系统，后台和其他局不能读取。编辑后以 worker 重建，后续变更防抖 750ms；生成新文件树后发布，移除旧树，停用条目、换卡和删局会清理相应产物。它们是世界书的派生副本，不作为独立编辑来源；下次读取时修复生成文件中的手工改动。该策略在游玩局中以 `read` 替换旧 `worldbook_search`，仅开放当前局生成文件。读取钩子只做同步和范围校验，文件 IO、分页和结果格式均由原生工具完成。卡片工作台和旧策略保持原有工具行为。原生 read 的按行、单行长度及输出量上限仍适用；原始正文资源本身没有截断或改写。宿主没有兼容原生 `read` 工具时不公布无法读取的目录。

同一执行轮内，未知副作用的批量预处理结果保持冻结；新增或修改的预处理控制器会留下诊断并在下一明确执行轮生效，删除和禁用立即撤销。带预处理控制器的书只有在原生运行时确认当前版本的条目可见性后才公布静态目录；编译阶段不会为此执行脚本。
