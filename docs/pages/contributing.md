# 贡献指南

欢迎给 DSH Tavern 提 PR！文档网站和酒馆程序都在同一个仓库里。不需要先成为开发者，也不需要做一个大功能：你使用时觉得哪里难懂、难找、麻烦，都可以从那里开始改。

## 哪些贡献都欢迎

- 改错字、补漏掉的步骤、修失效链接，把看不懂的说明改成人话。
- 写小白教程：从安装、配置模型到导入人物卡、开始第一局，告诉读者点哪里、填什么、成功后会看到什么。
- 给配置项、按钮或菜单改名，让人不用猜就知道它有什么用；补一句说明或一个例子也很好。
- 把不常用、复杂的配置放进默认折叠的“高级设置”，减少第一次使用时需要面对的选项。
- 调整界面布局、默认值和操作流程，改善手机体验、键盘操作或可读性。
- 修复 Bug、完善兼容性、补充示例、开发插件，或者提出新的功能。

这些只是例子。任何能让酒馆更好用、更容易理解的改动，都欢迎提出。小改动可以直接提 PR；涉及较大功能或行为调整时，可以先开 Issue 聊聊，也可以先提交草稿 PR 讨论。

## 上传一个 Markdown 文件，就能增加页面

把 `.md` 文件放进 `docs/pages/`，构建时就会自动生成网页、加入侧栏和搜索，不需要修改 JavaScript，也不需要写配置头。

例如新建 `docs/pages/first-game.md`：

```md
# 第一次开始游玩

这篇教程带你从导入人物卡到发出第一条消息。

## 开始之前

先配置好文字模型，其他高级设置可以暂时跳过。

## 操作步骤

1. 打开人物卡库。
2. 导入人物卡，再选择新建游玩。

也可以先阅读[开始第一局](#a04)。
```

文件名就是页面地址：这个例子会生成 `#first-game`。文件名使用小写英文字母、数字和连字符，不能与已有页面重名；正文第一行用 `# 中文标题`，它会成为页面和目录里的标题。无需写前置元数据。

直接放在 `docs/pages/` 的文章会出现在侧栏“帮助与维护”下面。想归到某个产品部分，就放进对应子目录，目录不存在时可自行创建：

| 目录 | 网站分组 |
| --- | --- |
| `docs/pages/play/` | 游玩模式 |
| `docs/pages/cards/` | 卡片模式 |
| `docs/pages/compatibility/` | 酒馆生态兼容 |
| `docs/pages/advanced/` | 高级功能 |
| `docs/pages/plugins/` | 插件 |
| `docs/pages/dshcard/` | DSH 人物卡 |
| `docs/pages/help/` | 帮助与维护 |

例如 `docs/pages/play/first-game.md` 会自动列入“游玩模式”，地址仍为 `#first-game`。同一分组的新文章按文件名排序。只支持上述一层分类目录，不要继续嵌套文件夹。

本篇贡献指南也通过这个机制生成，源文件就是 `docs/pages/contributing.md`。只扫描 `docs/pages/`，其他目录中的研究笔记不会自动公开。

## 正文怎么写

教程围绕一个具体目标，写清前提、操作和结果。步骤里使用当前界面上的实际名称，先写点哪里，再写做什么；复杂选项和原理放后面，告诉新手哪些可以跳过。

支持普通段落、二三级标题、单层有序／无序列表、表格、单行引用、围栏代码块、粗体、行内代码和链接。一级标题用于页面名称，正文从 `##` 开始。当前渲染器不支持完整 Markdown，嵌套列表、Markdown 图片和原始 HTML 暂不支持。

站内链接可直接写 `[开始第一局](#a04)`。在新文章之间，也可以使用相对 Markdown 链接，例如 `[第一次游玩](play/first-game.md)`；构建时会转换为站内地址。相对路径按当前文件位置计算，目标必须是 `docs/pages/` 中已有的页面。外部链接使用完整 `https://` 地址。

文件名决定公开地址，发布后尽量不改名，以免分享过的链接失效。构建会报告重复地址、缺少一级标题、未知分类目录和找不到目标的 Markdown 链接。

## 修改现有文档

新教程直接写 Markdown。旧功能说明暂时仍保留原有源文件，修改时可按下表查找；不要直接编辑生成的 `docs/index.html`。

| 想改什么 | 源文件 |
| --- | --- |
| 新增的 Markdown 页面 | `docs/pages/` 下的对应 `.md` 文件 |
| 产品概览、安装与启动 | `docs/manual/introduction.mjs` |
| 原有功能的操作步骤、结果和注意事项 | `docs/manual/topics.mjs` |
| 原有功能标题、入口和简述 | `docs/feature-inventory.md` |
| 原有目录和概览 | `docs/manual/navigation.mjs` |
| 插件开发、人物卡教程 | `docs/plugin-*.md`、`docs/dshcard-guide.md`、`docs/dshcard-tutorial.md` |
| 网站样式和手机排版 | `docs/assets/manual.css` |

已有功能说明中的 `page(...)` 参数依次是简介、步骤数组、结果、注意事项、相关功能编号数组。`A01` 和 `A02` 正文由 `introduction.mjs` 提供。

截图仍通过 `docs/manual/screenshots.mjs` 登记，图片放在 `docs/images/manual/`，通过 `pageScreenshots` 关联页面 ID；可以沿用现有条目。截图使用公开样例，去掉密钥和私人对话。

## 本地预览文档

只新增或修改 Markdown 时，可以直接上传文件；合并后网站工作流会自动构建。下面是需要提前看效果时的本地预览方法。

只改文档站时，需要 Node.js 22.19 或更新版本；下面的预览命令还需要 Python 3。文档构建使用 Node.js 内置模块，不需要先安装整个酒馆的依赖。

在仓库根目录执行：

```sh
node docs/manual/build.mjs
python3 -m http.server 4173 --bind 127.0.0.1 --directory docs
```

浏览器打开 `http://127.0.0.1:4173/`。每次改完源文件，重新运行构建命令，再刷新浏览器；这不是自动热更新服务。预览结束后，在终端按 Ctrl+C 停止。

提交前运行文档相关检查：

```sh
node --test tests/manual-site.test.mjs tests/product-site.test.mjs tests/manual-pages.test.mjs
```

如果已经安装 pnpm，也可以使用 `pnpm docs:dev`、`pnpm docs:build` 和 `pnpm test:docs`。本地构建更新了受跟踪的 `docs/index.html` 时，请把生成结果和源文件一起提交。

修改布局或交互时，再用浏览器看看电脑和手机窄屏下的效果，检查链接、搜索和浅色／深色主题。只改文档无需运行全部酒馆测试；修改程序时，运行与改动相关的测试，并在 PR 中说明验证结果。

## 发布

文档改动合并到 `main` 后，会触发仓库的 `Publish documentation` 工作流，构建检查通过并部署成功后更新网站。无需单独配置 GitHub Pages 或手动上传页面。
